## Anti-Patterns Verdict

**LLM assessment:** Partially. The product surfaces (login, users, history, roster, scan) are genuinely restrained — the kind a Linear/Stripe user would trust. The tells concentrate on the marketing shell: `app/page.tsx` has gradient text (`bg-clip-text bg-gradient-to-r`, L39), two animated `blur-3xl` orbs (L15–24), a pulsing "Institutional Grade System" pill, and a dead "View Live Screen" button (L59). Admin stat cards carry decorative `blur-xl` blobs + `hover:scale` + glow shadows (`app/admin/page.tsx`). A `border-l-[3px] border-primary` side-stripe on timetable events (`TimetableCalendar.tsx:172`) and `rounded-3xl` full-screen QR panels (`FullPageQRClient.tsx:133`) round it out. The hero-metric template (4 big numbers + uppercase tracked labels) repeats across admin, student, HOD, import — the exact SaaS cliché DESIGN.md anti-references.

**Deterministic scan:** `detect.mjs --json app components` exited 2, 5 findings across 3 rules. Genuine: `gradient-text` at `app/page.tsx:39`. Four `side-tab`/`border-accent-on-rounded` hits at `QRScanner.tsx:349–351` are the camera viewfinder reticle corners — **false positives** (required camera-guide UI, not decorative accents). Detector blind spots confirmed by grep: `TimetableCalendar.tsx:172` `border-l-[3px]` and `LiveSessionClient.tsx:407` `border-b-2` both evade the token matcher.

**Visual overlays:** Not available — no browser automation tool in this session. CLI source-scan is the evidence; no user-visible overlay was injected.

## Overall Impression

The core tool is quietly good: role-correct nav, one-click session start, a category-best QR scanner, real teaching empty states. The problem is the packaging around it. A dead/duplicate token file, a `.bg-white`→panel override that turns every white surface into a shadowed card, a brand-violating landing hero, and four competing modal implementations make the system feel like two different teams shipped two different products. The single biggest opportunity: point `/` at the real tool and strip the marketing layer — the register doesn't need a sales pitch.

## What's Working

1. **Faculty zero-friction start** — Session start is one click from `/faculty/dashboard`, with a strong active-session banner as reassurance. This is the 6x/day core flow and it's right.
2. **QR scanner quality** — `QRScanner.tsx` has zoom presets, tap-to-focus, haptics, retry, and camera-missing/permission states. Category-best.
3. **Teaching empty states** — Import and student surfaces explain the interface ("Import your first CSV") instead of "Nothing here".

## Priority Issues

- **[P1] Brand-violating landing page** (`app/page.tsx`). Gradient text, animated orbs, dead button, pulsing pill — every DESIGN.md ban on the first screen every user sees. Fix: strip the marketing layer, point `/` at role-based routing or the login card. Suggested: `$impeccable quieter`
- **[P1] Divided design system** — Two divergent token files (`styles/design-tokens.css` live RGB slate vs `app/styles/design-tokens.css` dead HSL teal/magenta); `.bg-white` override (`globals.css:58`) forces border+shadow onto every white surface, defeating flat-by-default. Fix: one token file, remove the override, decide shadows deliberately. Suggested: `$impeccable distill`
- **[P1] Inconsistent component vocabulary** — Three button grammars, four hand-rolled modals (only `ui/Modal.tsx` is correct: portal/dialog/focus-trap), `window.confirm`/`alert` across delete flows. Fix: one component set, a real confirm dialog. Suggested: `$impeccable polish`
- **[P2] Admin cognitive overload** — 10 sidebar items (should be ≤5, grouped); import entity picker shows 7 parallel cards. Suggested: `$impeccable shape`
- **[P2] High-frequency marking UX** — Roster Present/Absent targets ~26px on 60–70-row lists; no bulk-mark; end-session auto-mark-absent **defaults ON** for scheduled sessions (`LiveSessionClient.tsx:185`) — a rushed End can mass-mark students absent; the "Absent" stat count includes unmarked. Suggested: `$impeccable adapt` + `clarify`
- **[P3] Contrast fails** — `Badge.tsx` success #16a34a on success-bg = 3.0:1, error #dc2626 on error-bg = 3.95:1; hardcoded `text-green-500/600`, `text-red-500` on white fail 4.5:1. Suggested: `$impeccable audit`

## Persona Red Flags

**The busy professor (6 sessions/day):** Start-session is one click — the one strong bit. Under time pressure: row-level tap targets are ~26px and repeated 60+ times; no bulk "mark all present then fix exceptions"; the end-session auto-mark-absent default ON means a rushed End can write dozens of absences; mark failures surface as a thin red line at the page bottom, far from the row being marked.

**Alex (power user):** No keyboard shortcuts, no batch ops, dead topbar search, mocked notifications that never do anything — Alex clicks "Search" once and stops trusting the toolbar.

**Sam (accessibility):** Three hand-rolled modals lack focus-trap/`dialog` semantics; toggle is a `button` without `role="switch"`; live roster changes are color-only with no aria-live announcement; `surface-hover` row hover is barely perceptible and color-dependent.

**Casey (mobile):** Scan page is excellent (centered, big target, native zoom) but the roster marking is unusable on a phone with sub-44pt targets.

## Minor Observations

- Metadata says "Puff Attendance" (`app/admin/layout.tsx`) — third product name against "The Quiet Register" / sidebar "Register".
- `animate-in fade-in duration-200` classes assume the Tailwind Animate plugin, which isn't installed — those animations silently no-op.
- `bg-mesh-primary` / `bg-grid` are not defined Tailwind colors — likely resolve to no class (unstyled) on the landing hero.
- Student dashboard uses emoji (`🔒`/`🔓`) for the device-binding widget.
- Forgot-password surfaces a "⚙ Dev mode" reset link; login shows sample creds in placeholders.
- Import results draw ✓/–/✗ glyphs manually; entity picker shows "required columns:" inline per card.

## Questions to Consider

1. If you removed every landing accent and shadow, would the core tool lose anything a professor notices?
2. The register is built for a professor who needs 6 taps a day — but the landing and admin ornament are designed for a buyer nobody is selling to. Which one is the product?
3. Auto-mark-unmarked-as-absent is on by default. If a rushed faculty member ends a session badly and writes 30 absences by accident, what should the interface remember about them?
4. There are two competing token files in a repo with one committed palette. Why does the "quiet" system need two conflicting definitions of the same color?
5. What if the faculty sidebar was a single "Start Session" button and nothing else — surfacing tables only when needed?
